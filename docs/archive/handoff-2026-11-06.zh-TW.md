## 0. 30 秒版本

CRE8 正從 **pooled vault（共享金庫＋份額）** 遷移到 **ATP（Automated Token Portfolio，每人一個 non-custodial smart account）**，架構照 Glider。

程式碼已拆成三個獨立 repo（不在本 repo），第一版只做**股票指數**：

- **合約**：`AtpRegistry`（策略版本＋費率＋enroll）＋ `AtpExecutor`（唯一搬錢點，swap-only）＋ `PancakeV3TwapOracle`（TWAP 地板）
- **後端**：Bun + TypeScript + Postgres（raw `pg`，無 ORM），SIWE 認證＋策略鏡像上鏈＋enroll API
- **DB**：8 張表，3 個 migration

已驗證：Anvil fork BSC mainnet 上完成 auth → 建策略（鏈上 `onchainId=1`）→ 發版本 → enroll，`cast call enrollments` 回 `1/1/false`。

下一刀：**Kernel v3 smart account 部署**（現在 enroll 的 account 還是 EOA）。

## 1. 核心設計（main idea）

### 為什麼遷移

pooled vault 的風險是「集中式失敗」：單一合約 bug 或 curator 出錯可以一次掏空全池，加上份額／NAV 會計與「基金」的監管包袱。ATP 把資產留在使用者自己的帳戶，平台只做「權重＋排程」的執行與分發。

**代價（已接受）**：放棄績效費（原本 0–20% 建立人 + 10% 平台），收入改為 swap fee。

### 五層架構

```
⑤ 應用層   策略 = 指數定義（資產＋權重＋排程＋費率＋版本）
④ 執行層   鏈下 keeper（policy engine）＋ 簽名
③ 結算層   EntryPoint v0.7 + bundler（alto/ultra-relay）+ paymaster + eRPC
② 授權層   session key（Kernel permissions / SmartSession, ERC-7579）
① 帳戶層   Kernel v3 smart account（每人一個）
```

### 四條核心不變式

1. **規則在鏈下，資產在鏈上**，中間只靠 session key 的權限邊界。
2. **合約側唯一搬錢點是 Executor**；session key 只能呼叫它。
3. **每筆 swap 的淨產出（扣費後）≥ oracle 地板**：`minGross = ceil(oracleFloor / (1 − swapFeeBps/10000))`。
4. **策略是資料不是邏輯**：改權重／排程 = 發新版本，使用者不需重簽。

### 收費模型

| 費 | 扣在哪 | 誰拿 |
| --- | --- | --- |
| pool fee（0.05%／0.25%／1%） | swap 內，池子自己扣 | LP |
| 我們的 swap fee（30–300 bps） | swap 後、輸出側，Executor 切 | 我們（admin-only 可改） |
| infra fee／訂閱 | **暫緩**（原計畫走 x402 離線） | — |

### 技術選型（含理由）

| 決策 | 選擇 | 理由 |
| --- | --- | --- |
| 聚合器 | **PancakeSwap Universal Router**（不接 1inch） | BSC 上 PCS 流動性最深、bStock 池都在 PCS；少一個整合面 |
| 付款 | **Permit2**（`0x31c2F6fcFf4F8759b3Bd5Bf0e1084A055615c768`） | PCS v3 Universal Router 就是走 Permit2，實測直連 `approve` 會 `AllowanceExpired` |
| 價格地板 | TWAP（30–90 分）＋ 近期均值（5 分）雙窗口 | 擋 sandwich；費率併進 minOut 反推 |
| 後端語言 | Bun + TypeScript | 原生跑 TS，`bun test` 內建，與 web app 一致 |
| ORM | **不用**（raw `pg`） | schema 小且穩定；`db/` 的 SQL 是單一事實來源，ORM 的 codegen migration 會衝突 |
| 鏈 | mainnet 56 為主；dev 用 **Anvil fork** | fork 有真實 bStock＋PCS 池，且有免 faucet 的 funded 帳戶 |

## 5. 待辦（建議順序）

1. **Kernel v3 smart account 部署**（最重要）—— 現在 `smart_accounts.accountType` 還是 `EOA`，要改成真的 smart account，並在 enroll 時部署。
2. **session key 授權** —— 把「策略執行權」以 session key 授給 operator，取代現在的 owner-relayer。

6. **真實 mainnet 部署** —— 同一份 deploy script 換 `--rpc-url` 與 funded 帳戶。
7. **`GET /strategies/:id/versions`** —— 補了就能讓 201 帶 `Location`。

## 6. 已知坑（踩過的雷）

| 坑 | 說明 |
| --- | --- |
| **subagent allowlist 要新 session** | `fork` 會複製母 session 的 allowlist 快照，不重讀 profile。要開全新對話。 |
| **deepseek-official 的 flash 模型叫 `deepseek-flash`** | 不是 `deepseek-v4.1-flash`（那是 opencode-go 的 id）。用錯會直接被 allowlist 擋掉。 |
| **subagent 連續失敗** | 本輪有 3 個子代理「failed before finishing」，最後由主會話自己修。派工時要檢查檔案狀態再重派。 |
| **publicnode RPC 403** | fork 部署時會噴 archive 請求警告，但部署仍成功（CREATE 與建構子讀取只需最新 state）。 |
| **Anvil fork 地址每次可能不同** | 不要硬編碼，一律從 `broadcast/DeployAtp.s.sol/56/run-latest.json` 讀。 |
| **forge 不能在 cre8-protocol 跑** | 若 file policy 是 workspace-write（工作區 `bnb-agent-vaults`），`cre8-contracts` 的 `cache/` 寫不進去會報 `Operation not permitted`。 |
| **PCS affiliate 已退休** | 2025-03-05 結束，不能靠 PCS 分潤，要自己在 Executor 收費。 |
